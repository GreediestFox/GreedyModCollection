# 29 Clothing colour variants, female underwear items, release-process fix

- **Colour variants as standalone items** (`tools/apply_variants.py`, specs `tools/spec_male.json` / `spec_female.json`): 9 items 3995-4003 (Rags / North Rags / Steppe Rags / Simple Clothes in a colour or "Edel"), recipes 6700-6708 at Tailoring 60: colour = weaver's kit (295) + 1 dye (3982), Edel = Schneiderwerkstatt (2836) + 3 dye. A texture is bound to a mesh's material, so each variant needs its own mesh object: `dts_clone.py build <pristine dts> <out> <spec>` clones the objects with a new material; materials live in `art/materials_variants.cs` (exec'd from `materials.cs`), textures in `art/Textures/CharacterTextures/Outfits/Variants/`. The same `female.dts`/`male.dts` must be on the client and the dedicated server. Equip rows go into `cm_equipTypes.xml` (client + server data), DB rows into the tail of the server `art/dump.sql` (never a raw INSERT, it is wiped on boot), client rows into `objects_types.xml`, `recipe.xml`, `recipe_requirement.xml` (client requirement ids 300920+), German names into `data/loc/de/data/*_Name.xml`. The wardrobe-skin approach was dropped on purpose.
- **Female underwear** (`tools/apply_underwear.py`): the default underwear was only part of the character customisation (`data/cm_customisation.xml`, `Female_Underwear_*` meshes). Items 4004-4007 (Eur / Vik / Mon / Vik green clone), recipes 6709-6712 at weaver's kit, Tailoring 0, 3 cloth (the green one +1 dye); the underwear meshes were stripped from `cm_customisation.xml` (client and server) so new female characters spawn with body + `Female_Body_v1` texture only. Underwear shares body slot 2 with clothes (replaced, not layered).
- **Release process bug**: new files were not shipped between 1.0.62 and 1.0.89 because the pack is built from `inventory/*_vs_stock.csv`. Before every release run `compare_client.py` and `refresh_server_inventory.py`, then `build_pack.py`, diff the new manifest against the previous one, and delete a partial `release/<ver>` folder before `make_release.py`. A modified server file needs a stock copy in `stock/server`.
