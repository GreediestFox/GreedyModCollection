# 35 Wardrobe skins for everybody, LayDown/books/GM fixes, releases 1.0.108-1.0.124

- **Skins are the game's own wardrobe skins, not items.** The YO equipment data already defines every skin (317 numeric ids, including all armor, tool and weapon skins of the MMO). Standalone skin items (tried as releases 1.0.111-1.0.115: 15 tool, 226 armor and 67 weapon skins) were removed again (`tools/to_wardrobe.py` restores the originals). Two traps from that detour: an object type id must be <= 4095 on client AND server (`CmInventory: object type ID is too big` stops the client from entering the world), and a type that has children may not have a weight. The datablock `id` of a WeaponData is a SimDataBlock id (legal range 3..1026, unique across all scripts).
- **"Geh zum Shop" in the wardrobe** = the skin is not in the player's Steam inventory. The wardrobe lists the Steam item definitions in one pass and owned skins in a second pass; an old client-exe cave treated a table of ids as owned. `tools/patch_skin_table.py` moves that table into a new section (`.sknt`) filled with all skin ids and adds a first-pass check that skips ids already in the table (otherwise every skin is listed twice, once with a shop button). The server never checks skin ownership (`equipment_slots.SkinID` only). `gui/forms/skins.gui` (equip button always visible, buy button hidden) ships with it.
- **Client exe pin.** The patcher pins the client exe by sha256 (embedded resource `exepin/yo_cm_client.exe.txt`); every exe change needs a new patcher build, older patchers ignore a differently hashed exe and keep the old one. Fresh patcher builds are held by the virus scanner for about two minutes.
- **LayDown** (`client/scripts/LayDownClient/laydown.cs`): while lying only "forward"/jump stands the character up, sideways and backward are ignored, the body never turns, and free look is no longer restored with a stale value. Beds 84, 85, 523 and 3153 are in the ability's object list (`skill_types.xml` ability 276, client and server).
- **Books** (`client/scripts/Books/books.cs`, `server/mods/LiFx/BooksPack/mod.cs`): the ticket poll failed on the VPS with `Error downloading: 99 Error creating SSL context` because the client ships no OpenSSL DLLs, so the engine downloader needs a plain `http://` base URL (`booksHttp()`); the apply step now finds the blank book in equipment, a bag, or a bag in a bag (three container levels), and a pending document is retried.
- **GM `!give`** (`server/mods/LiFx/GMCommands/mod.cs`): items that do not stack (tools, clothes, furniture) ignored the quantity; the stack size is looked up first and such items are added one by one. Default durability is 100: an item with durability 0 counts as broken and its effects (rings, robes) do nothing.
- **The VPS is the real test server.** Fixes to the local server do nothing for players; every server-side change needs a VPS update (the other pack's server set, no LiFx framework).
- **Releases 1.0.108-1.0.124** are the pack itself and stay out of the repo; the repo keeps the sources, tools and these notes.
