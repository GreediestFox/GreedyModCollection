# 25 VPS operation: auto-start, Steam AppID, GM login, GM spawn lists

- **Auto-start** (`server/vps/Install_AutoStart_VPS.ps1`): scheduled task "LiF Server" (SYSTEM) runs `Start_LiF_Server_VPS.bat auto` at boot and every 5 minutes (the script exits at once when the server runs, so it is also a watchdog). Stop for maintenance: `Disable-ScheduledTask`, then `Stop-Process -Name ddctd_cm_yo_server -Force`. `LastTaskResult 267009` = task still running (fine). The start script does the one-time admin setup (Defender exclusion, firewall rules) only until `.setup_done` exists.
- **CR_STEAM_GAME_MISMATCH**: players hold tickets for AppID 290080, the server tool's own ID is 320850 and Steam updates/validation put it back into `steam_appid.txt`. The start script rewrites `steam_appid.txt` and sets SteamAppId/SteamGameId to 290080 on every start. Keep the Steam client closed on the server.
- **GM login on a fresh server**: the chat box cannot carry GM commands; the F6 panel and the console helper `gm("whoami")` (no `!`) use the local-chat command path. "GM Login - checking..." forever = the account is neither flagged IsGM nor in `$LiFxGM::accounts` (the mod then treats the command as normal chat and never answers). "Wrong Login" = account fine, password wrong; a copied `gm_password.cs` only matches the password it was made with: set a new one by writing it (6+ characters, one line) into `mods/LiFx/GMCommands/gm_setpass.txt`, no restart. Three wrong tries lock the account for 30 s. PowerShell .NET file calls need full paths.
- **GM panel spawn lists** (`client/scripts/GMHelper/gmobjects.cs`) are generated: `tools/gen_gmobjects.py` rebuilds them from the client's `objects_types.xml` + `cm_objects.xml` (commented-out rows and the hidden ID ranges stay out). Re-run after adding items, buildings or objects.
