# 38 Equipment rules (armor, ammo, hip slots) and the files a release was still missing

- **Equipment requirements** live in `cm_equipTypes.xml` (client and server must match): every type has `<skillID>`, `<skillAmount>` and `<slots>`. `tools/apply_equip_changes.py` sets all armor pieces (types whose only slot is 1-6, 381 of them) and the arrows/bolts to **Slinger (skill 47) amount 0**, i.e. nobody needs a skill to equip them, and gives the hand-and-a-half swords (object category 56 "Anderthalbhaender": Knight Sword, Practice Bastard, Bastard Sword, Big Falchion and their sharpened/perfect versions) the hip slots 10 and 11 next to the hands 12 and 13 (one-handed swords already have all four). There is no quiver item in the game, so "quiver" was read as the ammunition. Slot numbers: 1 helm, 2 body, 3 arms, 4 hands, 5 legs, 6 feet, 7/8 rings, 9 amulet, 10/11 hips, 12/13 hands, 14 tabard/banner, 17 fur collar.
- **Release 1.0.124-1.0.126 lesson:** the pack is built from a source folder while players run the full game install, so two kinds of files can be missing without any error on the builder's machine: (1) stock files that were edited in place (list them with `tools/list_modified_stock_files.py`), and (2) NEW non-stock files (`tools/list_extra_files.py`, then `tools/check_extra_files_referenced.py` keeps only those the shipped data names by exact path). Shipping datablocks that point to models/textures that are not shipped shows up in the client log of a fresh install as `failed to load thumbnail` lines for the missing paths; compare a tester's `C_*.log` with your own: identical error counts mean nothing new broke.
- **Cursor and night:** the custom cursor is two scripts (`core/scripts/gui/cursors.cs` with the hotspot and bitmap, `core/scripts/client/core.cs` calling `overridePlatformCursor(true)` so the software cursor is drawn); the darker night is the other pack's `art/datablocks/envData.cs` plus `art/Textures/Weather/raindrops.dds`.
