# 34 Steam-ID access (GM panel + VIP slots), the VPS layout, character creation, hair

- **GM panel by Steam ID** (`server/mods/LiFx/GMCommands`, `client/scripts/GMHelper/gmpanel.cs`): the password is gone. The Steam IDs in `steamids.cs` (`$LiFxGM::steamIds`) may open the panel with F6; the server reads the account's Steam ID from the database (`account.SteamID`, a bigint: keep it a STRING in TorqueScript) when the character enters the game, and answers the client's `!login` with `GMLoginResult` 1 (ok), 0 (not registered) or 3 (still checking). IsGM and the old account list no longer count. `!whoami` shows the Steam ID of anyone. The real IDs live only in the live `steamids.cs`/`config.cs`, the repo copies are empty.
- **VIP slots by Steam ID** (`VipSlotsPack`): the engine checks for a free slot in `GameConnection::onConnectRequest`, before the account is known. So the mod learns the connection address of every registered VIP when they enter the game and keeps it in `known_ips.cs` (written by the server, never shipped); a later connection from such an address counts as that VIP. A VIP must have joined once from the address they use. The old version never ran: the framework calls registered callbacks as METHODS (`%obj.func(args)`, `%this` first), but the mod registered a global function.
- **Hook the engine, not the framework**: both mods now override `GameConnection::onClientEnterGame` / `onConnectRequest` in their own package, so they work with or without the LiFx framework.
- **The VPS is a different server set** (the other pack's): no LiFx framework, our GM and VIP code live as copies in `scripts/lifmod/gm/gm_commands.cs` and `scripts/lifmod/vip/vip_slots.cs`, loaded by `scripts/lifmod/lifmod_init.cs` from `main.cs`. `tools/make_vps_lifmod_zip.py` builds the VPS update from our mods: paths `mods/LiFx/<mod>/` -> `scripts/lifmod/<gm|vip>/`, the registerCallback lines replaced by direct calls (`LiFxGMCommands::dbChanges()`, `::setup()`).
- **Client side too**: a client with `scripts/lifmod/GMHelper` (the other pack's loader) loads that copy after ours; regenerate it from `mod/GMHelper` with the path change.
- **Character creation** (`tools/merge_charcreat.py`): the one-race "Human" screen with all hair/beard styles is the other pack's Charcreat mod. Client files: `gui/forms/createCharacterWindow.gui` + `gui/scripts/createCharacterWindow.cs`, its `data/cm_customisation.xml` (client and server must be identical) with our female-underwear removal re-applied, and its message ids 691-696, 1021, 1257-1259 merged into ours (client + 12 loc files). Its exe patches (combat sum 60, server validators) are NOT in our pack.
- **Hair**: white baseline hair/beard textures replace the stock ones in `art/Textures/CharacterTextures/Customization/Female/Hair` and `.../male/Hair` (the male folder is lowercase on disk).
- **Release safety**: never ship per-player files (`data/prefs.cs`, hotbars, inventory, presets, `postfx.settings.cs`); patcher 1.0.6 refuses them by itself (source in the private GMC folder).
