# 32 Patcher 1.0.5 and the release 1.0.94 rebuild

The patcher source lives outside this repo (private GMC folder); this note records the behaviour.

- **Patcher 1.0.4**: `PathSafety` rejects anything under `logs/` and any `steam*.dll`, whatever the manifest says. The build script (`build_pack.py`) also skips `steam*.dll`.
- **Patcher 1.0.5**: exactly one executable may be shipped through the manifest: `yo_cm_client.exe` in the game folder root, and only if its SHA-256 equals the target hash compiled into the patcher's own exe patch. Everything else with an executable extension (and the same name with another hash) is still rejected; executables are never deleted. Before the download the existing exe is kept as `yo_cm_client.exe.gmc_stock` (`--restore-exe` still works). The manifest generator got `--allow-exe <name>=<sha256>` with the same rule. 72 unit tests.
- **Release 1.0.94** was built straight from the client folder as it was after a Steam uninstall (stock files gone), minus runtime/per-player data (`logs`, `screenshots`, `daemon`, hotbars, inventories, HUD presets, terrain cache, fonts, books cache, `*.dso` that have a script next to them), plus the patched exe from the full backup. The bucket was then cleaned: objects first, manifest last, then `rclone sync` of the object folder removed every object not in the new manifest (the patcher download zip and the status file in the bucket are separate and were kept). Known gap: the ~119 modified stock files of 1.0.93 (recipe/objects xml, loc files, some icons) are not in 1.0.94.
- **Lessons**: `build_pack.py` needs a complete client; a stripped folder crashes it on the first missing stock file. Never build a manifest `--previous` from a folder that lacks files, or the dropped files land in `delete` and the patcher removes them on players' machines.
