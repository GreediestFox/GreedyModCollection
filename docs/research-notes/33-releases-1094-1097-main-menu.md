# 33 Releases 1.0.94-1.0.97: stripped-client incident, main menu buttons

- **Incident**: after a Steam uninstall the client folder had lost its ~13.9k stock files, including the ~120 stock files our pack modifies (`data/skill_types.xml`, `recipe.xml`, `objects_types.xml`, loc files, some icons, ...). Releases 1.0.94/1.0.95, built from that folder, did not contain them, so a fresh install mixed stock data with our scripts and the client died at startup: `CmSkillsManager::_selectSkillTypes() - error alilities parsing` -> `Fatal: Can't load skills/abilities`. 1.0.96 restored every file of 1.0.93 from the full backup, hash-checked. Also forgotten in 1.0.94: `copyright.txt` (the patcher only warns).
- **Rule for releases**: build from a complete client and compare the new manifest with the previous one before uploading (no path of the old manifest may disappear unless intended).
- **1.0.97**: the dev button "Local Server (127.0.0.1)" (`QuickConnectLocal` in `gui/forms/MainMenuMultiplayerWindow.gui`, one-click connect to localhost without a password) was removed; the "Join a world" quick-join (`mod/QuickJoin/quickjoin.cs`) uses the current server password. The repo copy of QuickJoin keeps placeholders.
- **Connect errors**: `CR_INVALID_PASSWORD` = the password the client sends differs from `<password>` in the server's `config/world_1.xml` (read at server start; case-sensitive as far as seen). `<adminPassword>` is the GM password, not the join password. Two client places send a password: `directConnect.cs` in the game folder and `quickjoin.cs`.
